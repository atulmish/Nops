# Contributing to Nops

Thanks for your interest in improving Nops!

## Where to start

Look at the issues labelled [`good first issue`](https://github.com/atulmish/Nops/labels/good%20first%20issue) and [`help wanted`](https://github.com/atulmish/Nops/labels/help%20wanted), and at the [roadmap](ROADMAP.md). Comment on an issue before you start so that work is not duplicated.

## Development setup

1. Install the .NET SDK version pinned in `global.json`, and the .NET 8 runtime as well. The libraries and tests target `net8.0` and `net10.0`, and `dotnet test` runs both.
2. Clone the repository and build:

   ```bash
   dotnet build Nops.slnx
   dotnet test Nops.slnx
   ```

3. Before opening a pull request, make sure the format check passes:

   ```bash
   dotnet format --verify-no-changes
   ```

## Project layout

- `src/Nops.Core` - format parsing, stores, MAC verification, age and PGP master keys. This project must not reference any cloud SDK.
- `src/Nops.Core.AwsKms`, `src/Nops.Core.GcpKms`, `src/Nops.Core.Azkv`, `src/Nops.Core.Vault` - cloud master key providers.
- `src/Nops.Configuration` - ASP.NET Core `IConfiguration` integration.
- `tests/` - xUnit test projects, one per source project.
- `docs/` - user documentation (also published as the docs site; `docfx/` holds its configuration).
- `samples/` - runnable examples.

## Documentation site

The site at <https://atulmish.github.io/Nops/> is built with [DocFX](https://dotnet.github.io/docfx/) from `docs/` and the XML docs in `src/`, and published by `.github/workflows/pages.yml` when `main` changes. To preview it:

```bash
dotnet tool install --global docfx
docfx docfx/docfx.json --serve        # then open http://localhost:8080
```

Public members need XML doc comments: the build treats a missing one as an error. The logo and README graphics are generated by `python3 build/generate-brand.py`; edit that script rather than the images.

## Pull requests

- Add or update tests for behavior changes. CI enforces at least 95% line coverage (the report is in the job summary).
- Keep public API changes minimal and documented with XML doc comments.
- Cloud integration tests are skipped unless their environment is available (for example `AWS_LIVE_TEST=1` with LocalStack). Unit tests must pass without any cloud access.
- Describe what changed and why in the pull request body.

## Reporting bugs

Please use the GitHub issue tracker. Include the Nops package version, the file format (YAML, JSON, dotenv, INI, binary), and a minimal reproduction. Redact any real secrets from files you attach.

## Security issues

Do not open a public issue for security problems. See [SECURITY.md](SECURITY.md).
